Getting Paylance live

Everything below happens in your web browser. There is no code to write and nothing to install. Work top to bottom and tick each step off as you go — the page remembers where you got to, so you can stop and come back.

Part one

Set up the database

Supabase is where everything Paylance knows will live — your events, your tickets, who bought what. Right now the app has nowhere to put any of it, which is why nothing works yet.

01

Create a Supabase account

  1. Go to supabase.com
  2. Click Start your project
  3. Choose Continue with GitHub — it's the fastest, and you already have a GitHub account since your code lives there
  4. Approve the permission screen GitHub shows you
You'll know it worked You land on a mostly empty dashboard asking you to create your first project.
02

Create the project

  1. Click New project
  2. Name: type paylance
  3. Database password: click Generate a password, then copy it somewhere safe — your notes app, a password manager, anywhere you'll find it again
  4. Region: pick the one closest to your audience. For Nigeria that's usually West EU (Ireland) or Central EU (Frankfurt). If South Africa is offered, that works too
  5. Click Create new project and wait — it takes a minute or two
Save the password You won't need it for this guide, but if you ever lose it there's no way to recover it — only to reset it. Ten seconds now saves a headache later.
You'll know it worked The spinner finishes and you see your project's home page with charts on it.
03

Build the tables

Your project is empty. This step creates everywhere your data will go — events, ticket types, tickets, orders. It's one long block of text you copy from GitHub and paste into Supabase.

  1. Open setup.sql on GitHub
  2. Near the top right of the file, click the copy icon (two overlapping squares). That copies the whole file
  3. Go back to Supabase. In the left sidebar click SQL Editor
  4. Click into the big empty box and paste (Ctrl+V, or Cmd+V on a Mac)
  5. Click Run at the bottom right
You'll know it worked A green message: Success. No rows returned. That's the correct result — it means it built everything and had nothing to report back.
Safe to repeat If you're unsure whether it ran, just run it again. It's built to be run any number of times — it creates what's missing and skips what's already there. I tested this on a real database: three runs in a row, no errors.
04

Copy your three keys

These are how the app proves to Supabase that it's allowed in. You'll paste them into Vercel in Part Two, so keep this tab open — or paste them into a notes file for now.

  1. In the left sidebar, click the Settings gear at the bottom
  2. Click API (in newer projects it may say API Keys)

You need three values from that page:

On the Supabase pageSave it as
Project URL NEXT_PUBLIC_SUPABASE_URL
anon public
newer projects call this Publishable key		 NEXT_PUBLIC_SUPABASE_ANON_KEY
service_role secret
newer projects call this Secret key		 SUPABASE_SERVICE_ROLE_KEY
The third one is different The service_role key can do absolutely anything to your database — it ignores every security rule. It's safe in Vercel, where only your server can read it. Never paste it into a chat, a screenshot, a support ticket, or anywhere public.
05

Turn off email confirmation, for now

By default, anyone signing up has to click a link in their email before they can get in. That's right for launch, but it'll slow you down while you're testing your own product.

  1. In the left sidebar click Authentication
  2. Click Sign In / Providers (older projects: Providers)
  3. Click Email
  4. Switch Confirm email off and save
Turn this back on before you launch Without it, anyone can sign up with an email address they don't own. Fine while it's just you; not fine with real customers.

Part two

Put it on the internet

Your code is sitting on GitHub doing nothing. Vercel takes it and turns it into a real website with a real address you can send to people. It's free, and it connects to GitHub with a few clicks.

06

Merge the new work into your main code

Everything we've built — ticketing, the door scanner, the new landing page — is sitting on a side branch, not in your main code yet. Think of it as work finished but not yet filed. This puts it where Vercel will find it.

  1. Open this comparison page
  2. Click Create pull request
  3. Click Create pull request again on the next screen
  4. Scroll down and click Merge pull request, then Confirm merge
You'll know it worked A purple Merged badge appears at the top of the page.
07

Create a Vercel account

  1. Go to vercel.com/signup
  2. Choose Hobby — this is the free plan, and it's plenty to start
  3. Click Continue with GitHub and approve the permissions
08

Point Vercel at your code

  1. Click Add New… then Project
  2. Find ttickettailor-clone in the list and click Import
  3. If you don't see it, click Adjust GitHub App Permissions and give Vercel access to that repository

Don't deploy yet — there's a settings section to fill in first, on the very same screen. That's the next step.

09

Paste in your keys

On that import screen, expand Environment Variables. You'll add four. For each one, type the name in the left box and paste the value in the right box, then click Add.

Tap to copy each name so you don't mistype it:

NEXT_PUBLIC_SUPABASE_URL
NEXT_PUBLIC_SUPABASE_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY
NEXT_PUBLIC_SITE_URL

The first three take the values you copied in step 4. Leave the fourth one out entirely for now. You don't know your address yet, and the site works it out on its own until you do — you'll add it properly in step 11.

Don't put a stand-in value here This one setting decides where every ticket link in every email and WhatsApp message points. A made-up address here doesn't fail loudly — tickets still sell, mail still sends, and the links inside are simply dead. An empty box is safe; a placeholder is not.
Watch for stray spaces Pasting sometimes picks up a space at the end of a key. If something doesn't work later, this is the first thing to check.
10

Deploy

  1. Click Deploy
  2. Wait two or three minutes while it builds
You'll know it worked Confetti, and a screenshot of your landing page — the orange and purple one that says Sell tickets. Keep what you earn. Click it and you're looking at your live site.
11

Fix the site address

Vercel has now given you a real address, something like paylance-abc123.vercel.app. The app needs to know it, or the links inside ticket emails will point nowhere.

  1. Copy your site's address from the top of the Vercel page
  2. Go to Settings → Environment Variables
  3. Find NEXT_PUBLIC_SITE_URL, click Edit, and replace the placeholder with your real address
  4. Save, then go to Deployments, click the ··· menu on the top one, and choose Redeploy
Why the redeploy Changing a setting doesn't change the live site on its own — the site has to be rebuilt to pick it up. This catches almost everyone once.

Part three

Sell yourself a ticket

Worth doing once, start to finish, so you've seen the whole thing work before anyone else does. No real money moves — payments are in practice mode until you connect Paystack.

12

Make an account and connect a bank

  1. On your live site, click Get started and sign up
  2. Fill in onboarding
  3. Go to Payouts and connect a bank account. In practice mode any sensible-looking account number works — nothing is sent to a real bank
You can't skip the bank step Paylance refuses to publish a paid event until a bank account is connected — deliberately, so nobody can sell tickets with no way to be paid. Free events publish without one.
13

Create an event and buy a ticket

  1. Events → New event. Fill it in and save — it saves as a draft
  2. Open the event, click the Tickets tab. The price you typed is already there as General Admission
  3. Click Add type and make a second one — an Early Bird, cheaper, limit it to 5 — so you can see tiers working
  4. Click Publish, then Copy link
  5. Open that link in a private browsing window. This is what a buyer sees
  6. Pick a ticket, choose how many, enter a name and email, and pay
  7. On the practice payment screen, click Simulate successful payment
You'll know it worked You land on a confirmation page with a Show my tickets button. Click it — there's your ticket, with a QR code.
14

Scan it at the door

  1. Leave the ticket open on your computer screen
  2. On your phone, open your site, sign in, go to the event
  3. Tap Door
  4. Allow camera access, and point your phone at the QR code on your screen
You'll know it worked A green panel: Let them in. Scan the same code again and it turns amber — Already used. That's the whole product working.
If the camera won't open Browsers only allow the camera on secure addresses. Your Vercel address is secure, so this should work — but if it doesn't, tap Type it and enter the code printed under the QR instead. That always works.

If something breaks

The usual suspects

Almost everything that goes wrong here is one of these five things.

The site loads but nothing has any data in it

One of the two Supabase keys is wrong, or has a stray space on the end. Go to Vercel → Settings → Environment Variables, delete NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY, and add them again fresh from Supabase.

Then redeploy — settings changes don't take effect until you do.

Payment says it worked, but no order appears

That's SUPABASE_SERVICE_ROLE_KEY — missing, wrong, or you accidentally pasted the anon key into it. They look similar. Go back to Supabase and copy the service_role one specifically.

Your live site has a page that tells you this directly: add /integrations to the end of your address. It says exactly which keys it can and can't see.

"Connect a bank account before publishing a paid item"

Working as intended. Go to Payouts and connect one. It's blocked in three separate places on purpose, so there's no way to accidentally sell tickets with nowhere for the money to go.

Signing up seems to do nothing

Email confirmation is still switched on, and the confirmation email is sitting in your inbox or spam folder. Go back to step 5 and turn it off.

Nobody receives a ticket email

Expected for now — email is in practice mode until you add a Resend account, so messages are written to the server log instead of being sent. The tickets themselves are real: the buyer sees them on the confirmation page, and you can see every one in the event's Attendees tab.

Ask me when you want real emails switched on — it's one key and one setting.

When you're ready for real money

What's left

Everything above works with no payment account and no email account. Three things turn it into a real business, and none of them need doing today: a Paystack key so real cards work, a Resend key so tickets actually arrive by email, and your own domain name instead of the Vercel address.

One decision still open: the fee is ₦200 a ticket, but on a ₦100 ticket that's the entire ticket price. Before you launch you'll want either a minimum ticket price or a cap. It doesn't affect the ₦2,000-and-up tickets you're aiming at.
